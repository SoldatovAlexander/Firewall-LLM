# План реализации Firewall LLM (Python-MVP), TDD

## Принципы

1. **Red → Green → Refactor**: на каждый модуль сначала фейлящийся тест, потом код.
2. **Контракты раньше кода**: OpenAPI unified API и JSON Schema политик пишутся до
   реализации — они же общие с будущей Go-веткой.
3. **Пирамида тестов**:
   - Unit (pytest) — логика модулей, моки зависимостей
   - Integration — `respx` (мок HTTP к провайдерам), `testcontainers` (Redis/PG)
   - E2E — поднятый gateway против mock-провайдера; живой smoke против OpenRouter free
   - Contract — один набор тестов адаптеров, прогоняется для каждого провайдера
4. **Секреты только в `.env`**, в репо — `.env.example`.

## Инструменты

pytest, pytest-asyncio, respx, testcontainers, ruff, mypy,
FastAPI TestClient/httpx ASGI, Docker Compose (Prometheus, Grafana, Redis).

| FastAPI-приложение, `POST /v1/chat/completions` | Схема запроса/ответа соответствует OpenAPI (schemathesis); 422 на невалидном теле |

## Фаза 3. Metering (1 нед)

**DoD**: лимит токенов на клиента реально блокирует запросы.

## Фаза 5. Inspector: DLP (LightAnon) + prompt injection (1.5 нед)

| Задача | Тесты первыми |
|---|---|
| Цепочка инспекторов (request/response pipeline) | Юнит: порядок, режимы block/mask/log, короткое замыкание |
| `AnonymizeInspector` на LightAnon RAG-блоке | PII в промпте → уходит замаскированным; restore в ответе; TTL vault; политика mask vs restore |
| Стриминг + restore | Чанковый ответ восстанавливается корректно |
| Правила prompt injection (сигнатуры) | Корпус позитивных/негативных примеров → precision/recall порог в тесте |
| Событие `attack_detected{severity}` | Детекция публикует событие для роутера |

**DoD**: промпт с номером карты не уходит наружу в исходном виде; инъекция детектится.

## Фаза 6. Egress proxy pool (1 нед)

| Задача | Тесты первыми |
|---|---|
| Пул прокси, привязка к адаптеру | Юнит: выдача прокси по binding, round_robin/random/least_used |
| Ротация по количеству запросов | После N запросов на одном прокси — переключение на следующий |
| Healthcheck, исключение, cooldown | Упавший прокси (respx 500) выводится из ротации, возвращается после cooldown |
| HTTPS CONNECT через прокси | Smoke через локальный mitmproxy/squid-контейнер |

**DoD**: трафик к провайдеру идёт через назначенный пул, ротация работает.

## Фаза 7. Router + Policy Engine (1.5 нед)

| Задача | Тесты первыми |
|---|---|
| Парсер политик (JSON Schema) | Невалидная политика отклоняется, валидные кейсы из спецификации проходят |
| Оценка правил от событий (токены, RPS, атаки, error rate) | Юнит-симуляции последовательностей событий → ожидаемый routing table |
| Переключение провайдера mid-flight (новые запросы идут на backup) | Integration: превышение лимита → следующие запросы уходят на второй адаптер |
| Cooldown, ручной сброс, персистентность состояния в Redis | Рестарт процесса сохраняет активный маршрут |
| Маппинг моделей между провайдерами | `gpt-4o` → `claude-*` / free-модель OpenRouter по таблице |

**DoD**: сценарий «исчерпан бюджет токенов → автопереключение на бесплатную модель» проходит e2e.

## Фаза 9. Стабилизация

- Нагрузочное тестирование (k6/locust): latency overhead шлюза
- Docker Compose полного стенда + Helm-заготовка
- Документация: развёртывание on-prem, написание политик
- Решение по лицензии (FSL vs AGPL) перед публичным пушем
